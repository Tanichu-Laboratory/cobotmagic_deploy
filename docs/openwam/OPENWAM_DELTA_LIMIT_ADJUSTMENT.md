# Delta limit調査とIK精度調整（2026-09-24）

## ログで確認できた事実

- 044524（最新、111指令）: 左4・右2指令で旧delta limit表示。
  左位置誤差最大2.35 mm、右1.47 mm。
- 044441（90指令）: 左28・右13指令で旧delta limit表示。
  左の実測6関節は行46〜89、9.01秒間、完全に同一。
  受信ageは末尾でも約12 msなので、メッセージ受信途絶とは異なる。
  左J2は実測0.89327 rad、指令1.07327 radで実測差上限0.18 radに達し、
  モデル目標が進むにつれpublish前位置誤差は最大59.44 mmに拡大した。

実測が固定された理由（モータ停止・ドライバ・同じ値の再送など）は
これらのCSVには状態コードがなく断定できない。
上限緩和だけでは実機の追従を回復したことにならない。
実測差上限を1.5倍にした同一条件の試算でも、当該左腕の最大誤差は42.39 mm残った。
このため実測差・速度・加速度の上限値は据え置いた。

## 調整内容

従来の微分IKは、各局所反復で前回指令と初期姿勢を基準に正則化しており、
反復を重ねても目標との定常誤差を残し得た。
正則化を「その反復の関節修正量」に対して適用するように変更。
小さい特異値に対する減衰と全ての関節制約は維持したまま、
同一周期内の再線形化によって目標残差を減らす。
目標に一致しているのに過去の姿勢へ引き戻す動作はなくなる。

ログではactive_limitsに0始まりの関節番号を記録:
- measured_tracking: 実測との差の上限
- velocity: 前回publishからの速度上限
- acceleration: 指令速度の変化上限
- joint_position: URDFの可動域

旧表示はこれらを一括してdelta limitと呼び、unclipped値も
実際の無制約解ではなかった。微分IKではこの紛らわしい表示を廃止し、
制限種別と位置・姿勢残差、target_reachedを表示する。
目標精度内ならINFO、未到達ならWARN。CSVにはどちらも記録される。
可動域境界にいるだけではjoint_delta_limitedをtrueにしない。
