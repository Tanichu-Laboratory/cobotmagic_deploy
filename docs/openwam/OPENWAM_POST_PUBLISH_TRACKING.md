# OpenWAM publish後の追従誤差（2026-09-17）

対象: action_commands_20260917_111658.csv（95指令、94回の次周期比較、5 Hz、12 step消費）。比較用に110643、110943、111025も解析。実機publish・プロセス再起動・運用設定変更は行っていない。

## 比較方法と精度の限界

- 行iの `ik_joint_left/right`（実際にpublishする角度）と、行i+1の `ik_seed_joint_left/right`（次のIK開始前の実測関節）を比較。最後の指令は次回実測がないため除外。
- EEF位置・姿勢は双方の関節を同じ校正済みFKに通して比較。これはpublish後に追加される誤差であり、モデル目標とIK指令の間の誤差は含めない。
- 初回のik_seed_jointとcommand_beforeから運用時と同じ末端校正を再現。各行のcommand_fk_xyzとの差は全4実行で数値丸め以下。
- 姿勢誤差は回転行列の相対回転角。Euler角の単純差や位置・角度混合ノルムは使わない。
- `tracking_error_after` はこのEEFモードでは今回目標−前回指令で、実機の事後追従誤差ではない。
- wall_timeはpublish後に記録される一方、ik_seedはその行のIK計算前に取得される。厳密なpublish時刻・測定時刻・IK所要時間は記録されていない。以下は次周期比較であり、厳密に200 ms後の測定ではない。センサーの受信ageは最新ログで中央値7〜8 ms、最大約30 ms。通信・機械応答の遅延時間そのものはこのログだけで同定できない。
- 位置値はエンコーダとFKに基づく。指先のたわみや物体・カメラに対する絶対位置誤差を測定したものではない。

## 動作中と保持時の違い

最新ログの約0.56〜0.87秒のチャンク間隔7箇所では、位置誤差中央値は左0.432 mm・右0.326 mm、最大は左0.696 mm・右0.636 mm。各サンプルの6軸最大角度誤差は、最大でも左0.148°・右0.218°。異なる姿勢・指令量の比較なので、待ち時間だけの因果効果を証明するものではないが、固定的な関節対応の間違いより動作中の追従遅れを疑う結果。

全体最大位置誤差は左右とも最初の指令の次回観測（ログ間隔約147 ms）で、左5.339 mm・右16.433 mm。右はstep72にも14.792 mm（間隔約132 ms）。通常のログ間隔150〜300 msの85比較では、位置誤差最大は左2.781 mm・右5.530 mm。

関節3・5番の大きな角度差に対しEEF位置差は小さい例がある。右step85は関節3が−16.049°、関節5が+15.793°だが、位置差2.786 mm・姿勢差1.200°。位置誤差だけで全関節が追従していると判断できない。手首の運動学や指令の振れを含む原因の同定は別途必要。
